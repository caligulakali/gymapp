# PROJECT_SPEC.md — Техническое задание

## 1. Суть проекта

PWA-приложение для ведения личного журнала тренировок в спортзале. Пользователь
сам создаёт упражнения и шаблоны тренировок, записывает свои результаты,
хранит **все свои данные локально у себя** и может в любой момент выгрузить их
в понятном формате. Никаких подписок, аккаунтов и серверов — приложение
полностью принадлежит пользователю.

## 2. Цели

- Записывать прогресс в тренировках удобно и быстро.
- Полностью владеть своими данными (локальное хранение + экспорт/импорт).
- Лично анализировать свои тренировки.
- Настраивать интерфейс и контент под себя (свои упражнения, свои шаблоны).
- Работать как сайт-приложение (PWA): открывается в браузере, работает
  офлайн, устанавливается на телефон/компьютер.

## 3. Ключевые принципы (не нарушать)

1. **Данные принадлежат пользователю.** Никакой отправки данных на внешние
   серверы. Хранение — только локально (IndexedDB).
2. **Без платных подписок.** Приложение бесплатное, без скрытых функций.
3. **Удобный интерфейс.** Минимум кликов для записи тренировки, интерфейс
   для себя: тёмная тема, крупные кнопки, быстрый ввод.
4. **Личная аналитика.** Пользователь сам видит и анализирует историю,
   прогресс по упражнениям, веса, повторения.
5. **Форма PWA.** Один проект, работающий как сайт и как устанавливаемое
   приложение, в том числе офлайн.

## 4. Стадия 1 — функциональные требования

### 4.1. Упражнения (свои)

- Создание собственных упражнений:
  - название;
  - мышечная группа (грудь, спина, ноги, плечи, руки, пресс, кардио);
  - тип (силовое, кардио, на время, на количество);
  - единицы измерения веса (кг/фунты), ориентир по времени/расстоянию;
  - произвольные заметки;
  - список избранных упражнений.
- Редактирование и удаление упражнений (с предупреждением о влиянии
  на историю и шаблоны).

### 4.2. Шаблоны тренировок (свои)

- Создание шаблона тренировки:
  - название шаблона;
  - последовательность упражнений (порядок, количество подходов,
    целевые повторения, целевые весовые ориентиры);
  - заметки к шаблону.
- Редактирование, дублирование и удаление шаблонов.
- Заполнение шаблона из существующих упражнений + добавление новых.

### 4.3. Тренировки и история

- Начало тренировки: по шаблону или пустая (вручную).
- Запись выполнения: подходы, вес, повторения, время/расстояние,
  перерывы между подходами, ощущения/заметки.
- Завершение и сохранение тренировки с датой и временем.
- Просмотр истории тренировок (список за период, по шаблону, по упражнению).

### 4.4. Логирование и база данных

- Все данные хранятся в локальной базе данных в браузере (IndexedDB).
- Сущности БД: упражнения, шаблоны, тренировки, подходы/записи.
- Идемпотентность: повторные сохранения не дублируют данные.
- Миграции схемы базы при обновлении версии.

### 4.5. Экспорт данных и свой формат

- Экспорт всей истории и справочников (упражнения, шаблоны).
- Экспорт в стандартные форматы: JSON, CSV.
- Собственный формат GymApp (.gymapp):

  ```json
  {
    "format": "gymapp",
    "version": 1,
    "exportedAt": "2026-08-17T12:00:00.000Z",
    "exercises": [],
    "templates": [],
    "workouts": []
  }
  ```

- Импорт собственного формата (восстановление данных после переезда,
  сброса браузера, новой установки).
- Проверка целостности при импорте (версия формата, валидность сущностей,
  отчёт об ошибках при импорте).

### 4.6. Изменение тренировки

- Редактирование уже завершённой тренировки: правка подходов, добавление
  и удаление подходов/упражнений, изменение даты.
- История изменений не теряется: при первом импорте старых версий формата —
  корректное обновление.
- Удаление тренировки (с подтверждением).

## 5. Требования к интерфейсу

- Минимум кликов: запись подхода в 2-3 касания.
- Темная тема по умолчанию (и светлая опционально).
- Русский язык интерфейса.
- Адаптивность: телефон, планшет, десктоп.
- Чёткая навигация: главный экран (журнал), упражнения, шаблоны,
  статистика, экспорт/импорт.

## 6. Нефункциональные требования

- PWA: manifest, service worker, установка на устройство, полноценная
  работа офлайн.
- Работа без интернета и без аккаунтов.
- Аналитика прогресса временно исключена из текущего этапа разработки.
  Требования к прогрессу по упражнениям, частоте тренировок и графикам
  сохранены как отложенная функциональность и не входят в критерии готовности
  текущей реализации.
- Быстрый старт и отклик интерфейса.
- Код покрыт тестами для всех критических систем (см. AGENTS.md).

## 7. Дальнейшие стадии (вне стадии 1)

- Аналитика прогресса и графики (отложено; в текущую разработку не брать).
- Планирование тренировок (календарь).
- Калькуляторы (1ПМ, объём нагрузки).
- Кастомизация интерфейса для себя (свои поля, свои цвета).

### Статус аналитики

Аналитика пока не передаётся в разработку. До отдельного решения о начале
этой работы не реализовывать расчёты прогресса, графики, метрики частоты и
другие аналитические функции. Текущая разработка должна сосредоточиться на
журнале тренировок, упражнениях, шаблонах, истории и надёжности хранения и
экспорта данных.

## 8. Критерии приемки стадии 1

1. Создание, редактирование, удаление упражнений работает и данные
   сохраняются после перезагрузки страницы.
2. Шаблоны создаются из упражнений и разворачиваются в тренировку.
3. Тренировка записывается, завершается и редактируется.
4. История отображается и не теряется.
5. Экспорт (JSON/CSV/собственный формат) и импорт собственного формата
   работают, данные восстанавливаются корректно.
6. Приложение устанавливается как PWA и работает офлайн.
7. Все критичные системы покрыты тестами, ревью пройдены (см. AGENTS.md).
